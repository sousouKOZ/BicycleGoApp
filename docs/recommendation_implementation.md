# クーポン配布バランスとレコメンドロジックの改善計画

クーポンの「溜め込み（荒稼ぎ）」を防ぎつつ、アプリのコンセプトである「隠れた名店の発見（セレンディピティ）」をさらに促進し、直感的な理由を提示するためのアルゴリズム改修を行います。
（※リピート過多に対するペナルティ強化や未訪問店舗の底上げは先行して実装済みですが、本計画ではそれを土台にさらに高度な調整を行います）

## User Review Required

> [!IMPORTANT]
> **「おすすめ理由」の動的判定（案B：元の割合で比較）**
> 現在は「リピート回数が1以上なら無条件でリピートを理由にする」など固定の条件分岐（if-else）になっていますが、AIの計算上の重み付けに関わらず、そのお店の「一番満点に近い特徴」を理由として表示するように変更します。
> 以下の3つの「元のスコア（0.0〜1.0）」を比較し、最も点数が高いものを採用します。
> 1. 似たユーザーのおすすめ度（`s_item_cf`）
> 2. カテゴリの相性（`s_cat_cf`）
> 3. 個人のリピート実績（`s_personal`）
> 
> ※プロファイル（滞在型/通過型）はおすすめ理由から外し、純粋にこの3項目のみで比較します。
> ※もし点数が同率で並んだ場合は、「リピート > カテゴリ > 似たユーザー」の順で直感的にわかりやすい理由を優先して表示します。

## Proposed Changes

### Edge Functions (Supabase)

#### [MODIFY] `supabase/functions/issue_coupons/index.ts`
- クーポン抽選処理（Python API呼び出し）の前に、ユーザーが現在「所持している未使用のクーポン (`status = 'owned'`)」のリストをDBから取得します。
- 取得したリストを集計し、Python APIの `/api/v2/recommend` のリクエストボディ (`owned_coupons` 辞書、`{店舗ID: 所持枚数}`) として送信します。

#### [MODIFY] `supabase/functions/get_recommendations/index.ts`
- マップ表示（レコメンド取得）の際にも、同様にユーザーの未使用クーポンリストを取得して集計し、Python API に送信します。

---

### Python Recommendation API

#### [MODIFY] `recommendation_api.py`
- リクエストボディから `owned_coupons`（辞書）を受け取るように変更します。
- **ベーススコアの計算比率を変更**:
  `s_base = 0.5 * s_item_cf + 0.3 * s_cat_cf + 0.2 * s_personal` とし、個人の実績 (`0.3 -> 0.2`) よりもカテゴリの相性 (`0.2 -> 0.3`) や似たユーザー (`0.5`) をより重視した配点にします。
  ※先行実装した `s_base < 0.3` の場合のフォールバック（0.3への底上げ）は維持します。
- **未使用クーポンのペナルティ処理（溜め込み防止）**:
  スコア計算ループ内で、対象店舗のクーポンをすでに所持している場合、最終スコアに `0.3 ^ 所有枚数` を掛けてスコアを強制的に落とす（所有していると同じ店のクーポンが出にくくなる）処理を追加します。
- **おすすめ理由の判定ロジック**:
  `s_item_cf`, `s_cat_cf`, `s_personal` の3つの数値を比較し、最大値を持つ要素のテキストを理由として返します（すべて0の場合は距離や新規開拓を理由にします）。

## Verification Plan

### Automated Tests
- なし（ローカルデモ環境での手動テスト）

### Manual Verification
1. **理由の動的判定テスト**: アプリ上でマップを開き、表示される各店舗の「おすすめ理由」が多様な理由（似たユーザー、カテゴリ、リピートの3種類）に分散しているか確認する。
2. **溜め込み防止テスト**: 特定の店舗のクーポンを獲得（またはDBで強制的に `owned` のクーポンを作成）した状態で再度マップを開き、未使用クーポンを持つ店舗がマップ上のレコメンド順位で目立たなくなっている（スコアが下がっている）ことを確認する。
