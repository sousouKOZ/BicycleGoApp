# クーポン配布バランスとレコメンドロジックの改善計画

クーポンの「溜め込み（荒稼ぎ）」を防ぎつつ、アプリのコンセプトである「隠れた名店の発見」を促進するためのアルゴリズム改修を行います。

## User Review Required

> [!IMPORTANT]
> **「おすすめ理由」の動的判定（案B：元の割合で比較）**
> AIの計算上の重み付けに関わらず、そのお店の「一番満点に近い特徴」を理由として表示します。
> 以下の3つの「元のスコア（0.0〜1.0）」を比較し、最も点数が高いものを採用します。
> 1. 似たユーザーのおすすめ度（`s_item_cf`）
> 2. カテゴリの相性（`s_cat_cf`）
> 3. 個人のリピート実績（`s_personal`）
> 
> ※プロファイル（滞在型/通過型）はおすすめ理由として表示せず、純粋にこの3項目のみで比較します。
> ※もし点数が同率で並んだ場合は、「リピート > カテゴリ > 似たユーザー」の順で直感的にわかりやすい理由を優先して表示します。

## Proposed Changes

### Edge Functions (Supabase)

#### [MODIFY] `supabase/functions/issue_coupons/index.ts`
- クーポン抽選を行う前に、ユーザーが現在「所持している未使用のクーポン (`status = 'owned'`)」のリストをDBから取得します。
- 取得したリストを、Python APIの `/api/v2/recommend` のリクエストボディ (`owned_coupons` 辞書、店舗ID: 枚数) として送信します。

#### [MODIFY] `supabase/functions/get_recommendations/index.ts`
- マップ表示の際にも、同様にユーザーの未使用クーポンリストを取得し、Python API に送信します。

---

### Python Recommendation API

#### [MODIFY] `recommendation_api.py`
- リクエストボディから `owned_coupons` を受け取るように変更します。
- **ベーススコアの計算式を変更**:
  `s_base = 0.5 * s_item_cf + 0.3 * s_cat_cf + 0.2 * s_personal` とし、似たユーザー（50%）を重視した配点にします。
- **未使用クーポンのペナルティ処理を追加**:
  計算ループ内で、対象店舗のクーポンをすでに所持している場合、最終スコアに `0.3 ^ 所有枚数` を掛けてスコアを強制的に落とす処理を追加します。
- **おすすめ理由の判定ロジック**:
  プロファイルを比較要素から外し、純粋に `s_item_cf`, `s_cat_cf`, `s_personal` の3つの数値を比較し、最大値を持つ要素のテキストを理由として返します。

### Manual Verification
1. アプリ上でマップを開き、表示される各店舗の「おすすめ理由」が多様な理由（似たユーザー、カテゴリ、リピートの3種類）になっているか確認する。
2. クーポンを獲得した状態で再度マップを開き、未使用クーポンを持つ店舗がマップ上で目立たなくなっている（スコアが下がっている）ことを確認する。
